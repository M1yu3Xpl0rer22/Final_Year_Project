OWASP Top 10 (2025)

The standard awareness document for developers and web application security. ShieldByte protects against these critical risks.

A01: Broken Access Control

HIGH

Restrictions on what authenticated users can do are not properly enforced. Attackers can access unauthorized functionality and data.

A02: Cryptographic Failures

HIGH

Failures related to cryptography (formerly Sensitive Data Exposure), which often leads to sensitive data exposure or system compromise.

A03: Injection

CRITICAL

User-supplied data is not validated, filtered, or sanitized. Common types include SQL, NoSQL, OS command, and LDAP injection.

A04: Insecure Design

MEDIUM

Focuses on risks related to design flaws. A secure implementation cannot fix an insecure design.

A05: Security Misconfiguration

MEDIUM

Security settings are defined, implemented, and maintained with default values, incomplete configurations, or open cloud storage.

A06: Vulnerable Components

MEDIUM

Using components with known vulnerabilities (such as libraries, frameworks, and other software modules).

A07: Identification Failures

HIGH

Previously broken authentication. Confirmation of user's identity, authentication, and session management are critical.

A08: Software & Data Integrity

MEDIUM

Focuses on making assumptions related to software updates, critical data, and CI/CD pipelines without verifying integrity.

A09: Logging & Monitoring Failures

MEDIUM

Insufficient logging and monitoring allow attackers to maintain persistent access and avoid detection.

A10: Server-Side Request Forgery

MEDIUM

SSRF flaws occur whenever a web application is fetching a remote resource without validating the user-supplied URL.
