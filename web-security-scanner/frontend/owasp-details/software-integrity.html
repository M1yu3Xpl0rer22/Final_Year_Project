Software Integrity Failures

MEDIUM SEVERITY

Software and Data Integrity Failures relate to code and infrastructure that does not protect against integrity violations. This happens when you use software from untrusted sources or your CI/CD pipeline is compromised, allowing attackers to inject malicious code into your deployment process.

🔍 What Does It Look Like?

Downloading a plugin without checksum verification: 

wget http://untrusted-site.com/plugin.js

The file could be tampered with in transit or on the source server to include a backdoor.

🚨 Why It's Dangerous

  • Supply Chain Attacks (e.g., SolarWinds)
  • Deployment of malicious code to all users
  • Compromised update mechanisms
  • Extremely hard to detect once deployed

✅ How to Prevent It

  • ✓ Verify digital signatures or checksums of all software components.
  • ✓ Use trusted repositories (e.g., Maven Central, npm) with MFA enabled.
  • ✓ Secure your CI/CD pipeline and limit access.
  • ✓ Ensure specific versions are locked (pinned) in your dependency files.

💡 Secure Verification

❌ Insecure:

curl -O http://site.com/app.tar.gz
tar -xzf app.tar.gz

✅ Secure:

curl -O https://site.com/app.tar.gz
sha256sum -c app.sha256
