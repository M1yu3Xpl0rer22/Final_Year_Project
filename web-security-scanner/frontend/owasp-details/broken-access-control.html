Broken Access Control

HIGH SEVERITY

Broken Access Control happens when an application doesn't properly restrict what users can do or see. It means users might gain access to data or actions that should be off-limits to them — like viewing another user’s account details or deleting data they shouldn’t be able to.

🔍 What Does It Look Like?

Imagine you're logged in as a regular user, but by changing the URL from:

https://shieldbyte.com/user/view?id=101

to

https://shieldbyte.com/user/view?id=102

you can see someone else's private data.

🚨 Why It's Dangerous

  • Leads to unauthorized data leaks
  • Users can modify or delete sensitive info
  • May result in full account takeover
  • Violation of privacy compliance (GDPR, CCPA)

✅ How to Prevent It

  • ✓ Always check permissions on the server side — never trust hidden fields alone.
  • ✓ Use proper roles (admin, user, guest) and enforce them in middleware.
  • ✓ Deny access by default (minimize attack surface).
  • ✓ Log access violations and alert admins immediately.

💡 Example in Code

❌ Insecure:

if (request.user) { 
  showData(request.id); 
}

✅ Secure:

if (request.user.id === request.id || 
    request.user.role === 'admin') { 
  showData(request.id); 
}
