Insecure Design

MEDIUM SEVERITY

Insecure Design is a broad category representing flaws in architectural structure. It differs from insecure implementation: a perfect implementation of an insecure design is still insecure. This includes lack of threat modeling, insufficient secure design patterns, and failing to plan for security.

🔍 What Does It Look Like?

A "recover password" feature that asks for "Questions and Answers" which are easily researchable on social media (e.g., "Mother's maiden name"). This is a design flaw in the authentication flow.

🚨 Why It's Dangerous

  • Foundational flaws cannot be "patched" with code fixes
  • Requires architectural changes which are expensive
  • Can lead to business logic abuse

✅ How to Prevent It

  • ✓ Establish a secure development lifecycle with **Threat Modeling**.
  • ✓ Use secure design patterns and reference architectures.
  • ✓ Write unit and integration tests to validate critical flows.
  • ✓ Limit resource consumption by design (rate limiting).
