Cryptographic Failures

HIGH SEVERITY

Cryptographic Failures refer to weak, broken, or missing encryption that puts sensitive data at risk. This includes using outdated algorithms (MD5, SHA1), not encrypting data in transit, or hardcoding keys.

🔍 What Does It Look Like?

The most common example is transmitting sensitive data (like passwords) over plain HTTP:

POST http://example.com/login

Attackers on the same network can intercept this request and see the password in plain text.

🚨 Why It's Dangerous

  • Direct theft of passwords or credit cards
  • Man-in-the-Middle (MITM) attacks
  • Non-compliance with PCI-DSS and GDPR
  • Loss of user trust

✅ How to Prevent It

  • ✓ Force HTTPS everywhere — use HSTS headers.
  • ✓ Use modern algorithms like AES-256 and Argon2 for passwords.
  • ✓ Never commit secrets or API keys to version control.
  • ✓ Encrypt data at rest (database) and in transit (TLS).
