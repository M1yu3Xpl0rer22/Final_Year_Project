Injection

CRITICAL SEVERITY

Injection attacks occur when untrusted data is sent to an interpreter (SQL, NoSQL, LDAP, OS) as part of a command or query. The attacker's hostile data can trick the interpreter into executing unintended commands or accessing data without proper authorization.

🔍 The Classic Example

A login bypass using SQL Injection:

SELECT * FROM users 
WHERE user = 'admin' 
AND pass = '' OR '1'='1'

Because '1'='1' is always true, the database returns a record, logging the attacker in as admin.

🚨 Why It's Dangerous

  • Full database disclosure or loss
  • Authentication bypass
  • Remote Code Execution (RCE) in OS injection
  • High business impact and reputation damage

✅ How to Prevent It

  • ✓ Use Parameterized Queries (Prepared Statements) for all DB access.
  • ✓ Use ORMs (like Hibernate, Entity Framework) that handle escaping automatically.
  • ✓ Validate and sanitize input on the server side (allow-lists).
  • ✓ Limit database permissions (principle of least privilege).

💡 Example Fix

❌ Insecure:

"SELECT * FROM users WHERE user = '" + input + "'"

✅ Secure:

db.query("SELECT * FROM users WHERE user = ?", [input])
