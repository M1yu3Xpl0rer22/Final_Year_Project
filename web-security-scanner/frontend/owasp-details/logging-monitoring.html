Logging & Monitoring Failures

MEDIUM SEVERITY

Security Logging and Monitoring Failures occur when applications do not record security-critical events or fail to alert on them. Without adequate logging and monitoring, breaches may go undetected for days or months, making it impossible to stop attackers or determine the extent of the damage.

🔍 What Does It Look Like?

An API returning "403 Forbidden" 1,000 times in a minute for a single IP, but no alert is triggered.

// Silent failure
if (login_failed) {
  return error; // No log created
}

The attackers can brute-force indefinitely without being blocked.

🚨 Why It's Dangerous

  • Attackers dwell in systems undetected
  • Impossible to perform forensics after a breach
  • Regulatory non-compliance (PCI-DSS, HIPAA)
  • Inability to identify active threats

✅ How to Prevent It

  • ✓ Log all login failures, access control failures, and server-side input validation errors.
  • ✓ Ensure logs contain context (User ID, IP, Timestamp) but NO sensitive data.
  • ✓ Use centralized log management (SIEM) solutions.
  • ✓ Establish effective monitoring and alerting thresholds.

💡 Secure Logging

❌ Insecure:

console.log("Error occurred");

✅ Secure:

logger.warn("Auth failed", {
  user: "admin", 
  ip: "192.168.1.5",
  event: "BRUTE_FORCE_ATTEMPT"
});
